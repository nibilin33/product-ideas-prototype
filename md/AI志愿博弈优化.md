# 专利名称

> 一种基于多智能体博弈与风险约束的高考志愿优化系统及方法

---

# 一、场景来源（A＝场景来源）

## 1.1 行业背景

我国高考志愿填报涉及院校层级、专业偏好、地域因素、就业预期、家庭预算与政策约束的多维耦合决策，具有高风险、强时效、强不确定性特征。随着新高考改革推进，考生可选组合增多，传统经验式填报方式难以覆盖复杂约束。

典型应用场景包括：

- 普通本科批次考生在“冲稳保”结构下的志愿组合决策
- 同分段考生在不同省份、不同选科政策下的方案差异化选择
- 教育机构进行批量化、个性化志愿咨询服务

用户真实痛点包括：

- 录取概率难以量化，志愿选择依赖主观经验
- 只看分数线无法体现专业兴趣、能力匹配和职业目标
- 政策变化与数据波动导致方案易失效

---

## 1.2 现有流程

当前主流工作流程如下：

```text
考生输入成绩与偏好
 ↓
咨询师或家长人工筛选院校专业
 ↓
参考往年分数线与位次表
 ↓
静态生成冲稳保志愿表
 ↓
提交填报
```

---

## 1.3 存在的问题

- 现有流程偏静态，难以反映多考生竞争下的动态博弈关系
- 录取线预测通常单模型输出，缺乏不确定性建模与风险控制
- 优化目标单一，常仅追求录取率，忽视专业匹配、地域偏好和长期收益
- 方案更新滞后，政策或数据变动后需要大量人工重算

# 二、目标价值（A＝目标价值）

本发明希望实现：

1. 构建面向高考志愿场景的多智能体博弈优化框架
2. 在录取概率、专业匹配、风险控制之间实现多目标平衡
3. 提供可解释的志愿推荐结果与策略依据
4. 支持政策变化驱动的增量更新与快速重优化
5. 形成母专利加子专利的可拆分技术体系

技术价值：

- 将行为建模、预测、优化、博弈收敛与风险约束进行统一建模

商业价值：

- 显著提升志愿服务机构的方案质量、效率与可规模化交付能力

用户价值：

- 为考生提供更稳健、个性化、可解释的志愿决策支持

# 三、背景技术（A＝背景技术）

## 3.1 当前主流方案

方案A：基于历史分数线/位次的规则筛选方案

特点：

- 实现简单，易部署
- 可快速生成初步院校池

缺点：

- 难以应对策略互动与分布漂移
- 缺少多目标优化与风险控制

方案B：基于机器学习的录取概率预测方案

特点：

- 相比规则法有更强拟合能力
- 可输出细粒度概率估计

缺点：

- 常仅关注单任务预测，缺少端到端决策优化
- 缺乏博弈机制，易产生“模型好看但方案不稳”问题

---

## 3.2 目前存在的问题

① 考生行为异质性强，统一规则难以有效刻画

② 录取线变化受群体策略影响，单点预测偏差较大

③ 志愿填报本质是多目标约束优化，现有方案常降维过度

④ 政策变更后模型和规则重构成本高

⑤ 缺乏可验证收敛机制，推荐结果稳定性不足

## 4.2 核心创新点一

### 技术问题

现有方法将考生视为独立样本，忽略考生之间对同一院校专业的竞争耦合，导致推荐结果在真实填报环境中稳定性不足。

### 技术方案

构建“考生-院校-专业”三层异构图，并引入多智能体策略更新机制。每个考生智能体根据自身偏好、能力匹配、录取概率与风险预算迭代更新志愿序列；系统通过共享环境状态模拟群体竞争，计算策略收敛解。

#### 算法流程

```text
步骤1：构建考生智能体状态向量与动作空间

↓

步骤2：基于录取分布估计每个动作的期望收益与风险

↓

步骤3：按博弈更新规则同步或异步更新策略

↓

步骤4：判断收敛并输出稳定志愿组合
```

#### 数学建模

设第 i 个考生智能体策略为 $\pi_i$，联合策略为 $\Pi=(\pi_1,\pi_2,...,\pi_n)$，目标函数为：

\[
\max_{\Pi}\; \sum_{i=1}^{n}\left(\alpha P_i + \beta M_i + \gamma U_i - \lambda R_i\right)
\]

其中，$P_i$ 为录取概率收益，$M_i$ 为专业兴趣能力匹配收益，$U_i$ 为长期效用收益，$R_i$ 为风险惩罚项，且 $\alpha,\beta,\gamma,\lambda$ 为权重参数。

#### 伪代码

```python
initialize policies pi_i for each candidate i
for t in range(T_max):
	estimate admission_distribution under joint policy
	for each agent i:
		evaluate objective J_i = alpha*P_i + beta*M_i + gamma*U_i - lambda*R_i
		update pi_i by best-response or policy-gradient step
	if convergence_metric < epsilon:
		break
return stable policy set Pi
```

### 技术效果

- 将静态推荐提升为动态博弈优化，增强结果稳定性
- 在群体竞争场景下提升录取成功率与目标达成度
- 提供可验证的策略收敛条件和迭代过程

## 4.3 核心创新点二

### 技术问题

仅预测单一录取线点值难以支撑风险可控决策，无法区分“高期望但高波动”和“中期望但稳健”方案。

### 技术方案

提出动态录取线分布预测方法，输出分位数区间与尾部风险指标（如 CVaR）。在优化阶段引入风险约束，保证志愿组合满足用户可接受风险水平。

#### 算法流程

```text
步骤1：构建多源时序特征与政策特征

↓

步骤2：训练分布预测模型输出录取线分布

↓

步骤3：计算分位数、波动率与CVaR

↓

步骤4：将风险指标注入优化约束
```

#### 数学建模

\[
\min_{x} \; -\mathbb{E}[U(x)] + \eta \cdot \text{CVaR}_{q}(L(x))
\]

约束：

\[
	ext{CVaR}_{q}(L(x)) \leq \tau
\]

其中，$x$ 为志愿决策变量，$L(x)$ 为损失函数，$\tau$ 为风险预算。

#### 伪代码

```python
pred_dist = distribution_model(features)
risk = compute_cvar(pred_dist, q)
solve optimization:
	maximize expected_utility(x)
	subject to cvar_loss(x) <= tau
return feasible solution x
```

### 技术效果

- 从点预测升级为分布预测，提升风险感知能力
- 支持按风险偏好定制“冲稳保”比例
- 降低高风险志愿集中导致的失败概率

---

## 4.4 核心创新点三

### 技术问题

政策变更（招生计划、选科要求、批次规则）会迅速使既有模型失效，传统全量重训成本高、响应慢。

### 技术方案

提出政策变化增量更新机制：通过变化检测器识别规则影响范围，仅对受影响子图与特征子空间进行局部更新；同时维持历史策略记忆，减少收敛迭代次数。

#### 算法流程

```text
步骤1：检测政策与数据变化事件

↓

步骤2：定位受影响院校专业子图

↓

步骤3：执行局部模型更新与参数蒸馏

↓

步骤4：进行快速重优化并输出新方案
```

#### 伪代码

```python
delta = detect_policy_change(policy_stream)
affected_subgraph = locate_impact(delta, graph)
update_models_locally(affected_subgraph)
warm_start_from_previous_policy()
rerun_game_optimization()
return updated_recommendation
```

### 技术效果

- 显著缩短政策变化后的模型响应时间
- 降低全量重算成本，提升系统可运营性
- 保持历史策略连续性，减少结果抖动

---

## 4.5 核心创新点四

提出专业兴趣能力匹配机制，将课程成绩、能力标签、职业偏好向量与专业画像向量进行对齐，作为优化目标中的长期收益项，提高“录得上且读得好”的方案质量。

## 4.7 算法伪代码

```python
def recommend(student, history_data, policy_data, constraints):
	features = build_features(student, history_data, policy_data)
	graph = build_heterogeneous_graph(features)

	admission_dist = predict_admission_distribution(graph)
	match_score = compute_interest_ability_match(student, graph)
	risk_score = estimate_risk(admission_dist)

	init_plan = multi_objective_optimize(
		admission_dist=admission_dist,
		match_score=match_score,
		risk_score=risk_score,
		constraints=constraints,
	)

	stable_plan = multi_agent_game_refine(init_plan, graph, constraints)
	final_plan = enforce_risk_budget(stable_plan, constraints)

	return explain(final_plan)
```

## 4.8 时间复杂度

设考生数量为 $n$，候选院校专业节点数为 $m$，博弈迭代轮次为 $k$：

```text
关系图构建：O(n + m + e)

分布预测：O(m log m)

多目标优化：O(m^2)

博弈迭代：O(k * n * m)

增量更新：O(delta_m log m)
```

其中 $e$ 为边数，$delta_m$ 为受政策变化影响的子节点规模。
