# 专利名称

> 一种用于高考志愿填报的多智能体志愿博弈模拟方法、系统及存储介质

---

# 一、场景来源（A＝场景来源）

## 1.1 行业背景

高考志愿填报并非单个考生的独立决策问题，而是大量考生在有限招生计划约束下的竞争性决策问题。各考生对院校与专业的选择会相互影响，进而改变录取门槛与录取概率分布。

在实际业务中，教育机构通常需要为同分段、同省份、同批次的多个考生并行生成志愿方案。若忽略群体竞争关系，方案在真实填报环境中容易出现偏差。

典型场景包括：

- 大规模平行志愿填报前的策略推演
- 高热度专业集中报考下的拥挤风险评估
- “冲稳保”结构比例的动态调整

---

## 1.2 现有流程

现有常见流程如下：

```text
输入考生画像与偏好
 ↓
单体模型计算录取概率
 ↓
按概率与偏好排序生成志愿表
 ↓
人工微调后输出
```

---

## 1.3 存在的问题

- 将考生视为相互独立样本，无法刻画策略联动效应
- 推荐结果缺少博弈迭代过程，稳定性和可重复性不足
- 对热门院校专业拥挤度缺乏显式建模
- 在批量生成场景下难以保证群体层面的整体最优

---

# 二、目标价值（A＝目标价值）

本发明希望实现：

1. 建立考生群体间相互影响的多智能体志愿博弈模型
2. 在录取收益、偏好满足与风险约束之间实现协同优化
3. 输出具备收敛性与稳定性的志愿策略组合
4. 支持大规模并发考生的快速模拟与重计算
5. 为母专利系统提供可拆分、可复用的博弈核心引擎

技术价值：

- 将志愿推荐从静态排序升级为动态博弈求解

商业价值：

- 提升机构级批量咨询的方案一致性与成功率

用户价值：

- 降低热门志愿拥挤带来的录取不确定性

---

# 三、背景技术（A＝背景技术）

## 3.1 当前主流方案

方案A：规则引擎与经验打分法

特点：

- 实现简洁，解释直观
- 可快速上线

缺点：

- 对策略交互反应迟钝
- 难以量化群体竞争影响

方案B：单考生机器学习推荐法

特点：

- 能学习历史录取模式
- 可输出个体化建议

缺点：

- 通常忽略考生间耦合关系
- 结果在群体同时决策时易失稳

---

## 3.2 目前存在的问题

① 无法统一建模“个体理性”与“群体竞争”

② 缺少收敛判据，迭代更新容易震荡

③ 缺少拥挤惩罚机制，易过度集中热门志愿

④ 缺少可扩展框架，难以服务万级考生并行模拟

⑤ 缺少与风险约束和政策更新模块的标准接口

## 4.2 核心创新点一

### 技术问题

传统志愿推荐把考生看作独立决策者，无法描述考生之间对同一志愿资源的竞争。

### 技术方案

构建“考生智能体-院校专业资源位”的双层博弈环境。每个智能体在给定风险预算下选择动作（志愿序列调整），环境根据总体报考分布反馈拥挤度与录取概率变化。

#### 算法流程

```text
步骤1：初始化每个考生智能体策略

↓

步骤2：根据全体策略估计各志愿拥挤度

↓

步骤3：计算每个智能体的即时收益与惩罚

↓

步骤4：执行策略更新并进入下一轮
```

#### 数学建模（可选）

设第 $i$ 个智能体策略为 $\pi_i$，候选志愿动作为 $a_i$，联合策略为 $\Pi$，其效用定义为：

\[
U_i(a_i, \Pi_{-i}) = \alpha P_i + \beta M_i - \gamma C_i - \lambda R_i
\]

其中，$P_i$ 为录取收益，$M_i$ 为偏好匹配收益，$C_i$ 为拥挤惩罚项，$R_i$ 为风险惩罚项。

#### 伪代码

```python
for t in range(T_max):
    congestion = estimate_congestion(all_agents_policy)
    for agent in agents:
        payoff = alpha*admit_prob(agent) + beta*match_score(agent) \
                 - gamma*congestion_penalty(agent, congestion) \
                 - lam*risk_penalty(agent)
        agent.policy = update_policy(agent.policy, payoff)
```

### 技术效果

- 显式建模群体竞争，降低热门志愿过度集中
- 提升群体层面录取效率与稳定性
- 为后续收敛控制提供统一收益表达

---

## 4.3 核心创新点二

### 技术问题

多智能体更新过程中容易出现策略震荡，导致结果不稳定。

### 技术方案

提出“温度退火 + 最优响应混合更新”机制。前期高探索、后期高利用；并引入策略平滑项，约束相邻轮次策略差异，抑制震荡。

#### 算法流程

```text
步骤1：设定初始温度与退火计划

↓

步骤2：执行混合更新（最优响应 + 概率采样）

↓

步骤3：引入策略平滑约束

↓

步骤4：根据稳定性指标动态调整步长
```

#### 数学建模（可选）

\[
\pi_i^{t+1} = (1-\rho_t)\,\pi_i^{t} + \rho_t\,\hat{\pi}_i^{t}
\]

其中，$\hat{\pi}_i^{t}$ 为第 $t$ 轮最优响应，$\rho_t$ 为与温度相关的更新率。

#### 伪代码

```python
temperature = T0
for t in range(T_max):
    rho = schedule(temperature, t)
    for agent in agents:
        br = best_response(agent, env_state)
        agent.policy = (1 - rho) * agent.policy + rho * br
    temperature = cool_down(temperature)
```

### 技术效果

- 降低策略震荡，提高收敛速度
- 增强不同初始条件下的结果一致性
- 提升工程可复现性

---

## 4.4 核心创新点三

### 技术问题

缺乏可量化的收敛判定标准，无法判断何时输出最终方案。

### 技术方案

提出多指标收敛判据：联合策略变化量、群体平均收益增益、拥挤度方差下降率三者共同满足阈值时判定收敛；并加入回退机制防止局部异常波动。

#### 算法流程

```text
步骤1：计算策略变化范数

↓

步骤2：计算群体收益增量

↓

步骤3：计算拥挤度方差变化

↓

步骤4：满足联合阈值则停止迭代
```

#### 数学建模（可选）

设收敛条件为：

\[
\|\Pi^{t+1}-\Pi^t\|_2 < \epsilon_1,
\quad
\Delta \bar{U}^t < \epsilon_2,
\quad
\Delta Var(C)^t < \epsilon_3
\]

#### 伪代码

```python
if policy_delta < eps1 and utility_gain < eps2 and congestion_var_drop < eps3:
    converged = True
```

### 技术效果

- 提供可审计、可解释的停止条件
- 提升输出方案稳定性与一致性
- 降低过度迭代带来的计算开销

## 4.5 核心创新点四

提出“分层并行博弈”机制，先在省份/科类层进行粗粒度均衡，再在院校专业层进行细粒度优化，以提升万级考生场景下的计算效率。

---

## 4.6 整体算法流程

```text
输入：考生群体数据、院校专业池、约束参数

↓

数据预处理：清洗、标准化、候选筛选

↓

特征建模：构建智能体状态向量与动作空间
```

## 4.7 算法伪代码

```python
def game_simulate(candidates, options, constraints):
    agents = init_agents(candidates, options)
    env = init_environment(options, constraints)

    for t in range(constraints.max_iter):
        env.update_congestion(agents)

        for agent in agents:
            utility = compute_utility(agent, env, constraints)
            action = select_action(agent, utility, constraints)
            agent.apply(action)

        metrics = evaluate_convergence(agents, env)
        if metrics.is_converged:
            break

    return export_plans(agents, env)
```

## 4.8 时间复杂度

设考生数为 $n$，候选志愿动作数为 $m$，迭代轮次为 $k$：

```text
状态初始化：O(nm)

拥挤度估计：O(nm)

单轮策略更新：O(nm)

总迭代复杂度：O(k*n*m)

并行分层后近似复杂度：O(k*n*m/p)
```

其中 $p$ 为并行处理单元数量。
