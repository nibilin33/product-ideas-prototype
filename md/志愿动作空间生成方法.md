# 专利名称

> 一种面向高考志愿优化的志愿动作空间生成方法、系统及存储介质

---

# 一、场景来源（A＝场景来源）

## 1.1 行业背景

高考志愿优化本质是约束条件下的组合决策问题。考生需要在有限志愿位内完成院校与专业排列，同时满足选科要求、批次规则、地域偏好、费用约束及风险偏好。

现有智能推荐系统通常直接进行排序或打分，但缺少对“可行动作”的系统化建模，导致优化过程中的搜索空间要么过大无法收敛，要么过窄难以找到高质量方案。

典型应用场景包括：

- 志愿初始方案生成后的局部改进
- “冲稳保”结构的自动重排
- 政策变更后的快速可行动作重建

---

## 1.2 现有流程

现有常见流程如下：

```text
输入考生画像与约束
 ↓
模型打分得到候选院校专业
 ↓
直接排序输出志愿表
 ↓
人工调整少量项
```

---

## 1.3 存在的问题

- 缺少动作空间定义，优化算法无法明确“可改什么”
- 合法性校验与动作生成耦合混乱，易产生不可执行方案
- 候选动作数量爆炸，计算代价高、收敛慢
- 无法按风险偏好动态调整动作集合

---

# 二、目标价值（A＝目标价值）

本发明希望实现：

1. 构建标准化、可约束、可扩展的志愿动作空间生成机制
2. 保证动作集合的合法性、可执行性与可解释性
3. 在动作规模可控的前提下覆盖高价值改动方向
4. 支持不同风险偏好与政策条件下的自适应动作生成
5. 为多目标优化与多智能体博弈提供统一输入接口

技术价值：

- 将“志愿优化”从直接排序升级为“动作空间驱动的策略搜索”

商业价值：

- 降低机构人工调参成本，提高批量化交付效率

用户价值：

- 获得更稳健且可解释的志愿调整建议

---

# 三、背景技术（A＝背景技术）

## 3.1 当前主流方案

方案A：基于静态候选池的直接排序方法

特点：

- 实现简单、上线快
- 便于输出初版志愿结果

缺点：

- 不显式建模“动作”，难以迭代优化
- 局部替换与结构调整能力弱

方案B：基于启发式规则的局部修正规则方法

特点：

- 可嵌入业务经验
- 对少量典型场景有效

缺点：

- 规则碎片化，泛化能力弱
- 难以平衡合法性、规模和收益

---

## 3.2 目前存在的问题

① 动作定义不统一，系统间难以复用

② 合法动作与非法动作混杂，校验成本高

③ 动作组合呈指数增长，搜索易失控

④ 缺乏风险与偏好驱动的动作筛选机制

⑤ 难以与博弈、收敛和增量更新模块协同

## 4.2 核心创新点一

### 技术问题

现有志愿优化缺乏统一动作表示，导致不同算法之间难以共享同一搜索空间。

### 技术方案

提出志愿原子动作标准表示，将动作定义为五元组：

\[
a = (type,\ target,\ position,\ scope,\ constraint\_tag)
\]

其中，$type$ 包括插入、删除、替换、交换、位移；$target$ 为院校专业对象；$position$ 为志愿位置信息；$scope$ 为批次或层级范围；$constraint\_tag$ 为约束标签。

#### 算法流程

```text
步骤1：读取当前志愿序列与候选池

↓

步骤2：按动作类型生成原子动作模板

↓

步骤3：绑定目标对象与位置参数

↓

步骤4：输出标准化原子动作集合
```

#### 伪代码

```python
def build_atomic_actions(plan, candidate_pool, constraints):
	actions = []
	for item in candidate_pool:
		actions.append(Action("insert", item, None, item.batch, constraints.tag))
	for idx, cur in enumerate(plan):
		actions.append(Action("delete", cur, idx, cur.batch, constraints.tag))
		for alt in candidate_pool.by_batch(cur.batch):
			actions.append(Action("replace", (cur, alt), idx, cur.batch, constraints.tag))
	return actions
```

### 技术效果

- 实现动作定义统一化与可复用化
- 便于后续优化算法直接调用
- 提升系统可扩展性与工程一致性

---

## 4.3 核心创新点二

### 技术问题

动作空间规模增长过快，导致优化效率低且易陷入计算瓶颈。

### 技术方案

提出“合法性先验过滤 + 收益上界剪枝 + 多样性保留”三级筛选机制：

- 第一级：根据政策、选科、批次、计划数等硬约束过滤非法动作
- 第二级：估计动作收益上界，删除低上界动作
- 第三级：按院校层级、地域、专业类目进行分桶采样，保留多样性

#### 数学建模（可选）

设动作集合为 $A$，合法集合为 $A_f$，剪枝后集合为 $A_p$：

\[
A_f = \{a \in A \mid g(a)=1\}
\]

\[
A_p = \{a \in A_f \mid \hat{U}(a) \ge \theta\}
\]

其中，$g(a)$ 为合法性判定函数，$\hat{U}(a)$ 为收益上界估计，$\theta$ 为阈值。

#### 算法流程

```text
步骤1：硬约束合法性判定

↓

步骤2：收益上界计算与阈值剪枝

↓

步骤3：分桶采样保留动作多样性

↓

步骤4：得到可控规模动作集合
```

#### 伪代码

```python
def prune_actions(actions, constraints, theta, bucket_quota):
	legal = [a for a in actions if is_legal(a, constraints)]
	high_value = [a for a in legal if upper_bound_gain(a) >= theta]
	return diversity_sample(high_value, bucket_quota)
```

### 技术效果

- 显著降低动作规模与计算开销
- 在规模可控下保持高价值动作覆盖
- 提升全局优化收敛速度

## 4.4 核心创新点三

### 技术问题

不同用户风险偏好下，动作优先级不同，固定动作空间无法适配个体需求。

### 技术方案

引入风险偏好条件化动作生成机制。根据风险等级动态调节动作类型权重，例如高风险用户提高“上探位移/替换”动作比例，低风险用户提高“下沉保底/稳态交换”动作比例。

#### 数学建模（可选）

对动作 $a$ 的优先分数定义为：

\[
S(a|r)=w_1(r)\cdot G(a)+w_2(r)\cdot M(a)-w_3(r)\cdot Q(a)
\]

其中，$r$ 为风险档位，$G(a)$ 为收益增益估计，$M(a)$ 为偏好匹配增益，$Q(a)$ 为风险惩罚。

#### 算法流程

```text
步骤1：识别用户风险档位

↓

步骤2：加载对应权重配置

↓

步骤3：计算动作条件化优先分数

↓

步骤4：按分数输出个性化动作空间
```

#### 伪代码

```python
def personalize_actions(actions, risk_level, weight_table):
	w1, w2, w3 = weight_table[risk_level]
	scored = []
	for a in actions:
		s = w1*gain(a) + w2*match_gain(a) - w3*risk_penalty(a)
		scored.append((a, s))
	scored.sort(key=lambda x: x[1], reverse=True)
	return [a for a, _ in scored]
```

### 技术效果

- 动作空间能够适配不同风险偏好
- 提升个性化推荐质量
- 降低“统一策略”导致的误配风险

## 4.6 整体算法流程

```text
输入：考生画像、当前志愿序列、候选池、规则约束、风险偏好

↓

数据预处理：标准化院校专业编码与约束标签

↓

特征建模：构建动作所需收益、风险与匹配特征

↓

AI推理：估计动作收益上界与风险代价

↓

规则生成：原子动作和组合动作生成

↓

反馈优化：合法性过滤、剪枝、个性化排序

↓

输出：可执行且可控规模的动作空间
```

## 4.7 算法伪代码

```python
def generate_action_space(student, plan, candidate_pool, constraints, risk_level):
	normalized = normalize_constraints(constraints)
	atomic_actions = build_atomic_actions(plan, candidate_pool, normalized)
	combo_actions = compose_actions(atomic_actions, normalized.max_combo_len)

	filtered = prune_actions(
		actions=combo_actions,
		constraints=normalized,
		theta=normalized.gain_threshold,
		bucket_quota=normalized.bucket_quota,
	)

	ranked = personalize_actions(
		actions=filtered,
		risk_level=risk_level,
		weight_table=normalized.weight_table,
	)

	return ranked[: normalized.max_actions]
```

## 4.8 时间复杂度（可选）

设当前志愿长度为 $n$，候选池规模为 $m$，组合动作最大长度为 $l$：

```text
原子动作生成：O(nm)

组合动作生成（受限）：O(nm*l)

合法性过滤：O(|A|)

收益评估与排序：O(|A| log |A|)

总复杂度：O(nm*l + |A| log |A|)
```

其中 $|A|$ 为过滤前动作数量，经过剪枝后可近似控制在 $O(nm)$ 量级。

## 实施例二

输入：

- 同一考生群体，分别设定高风险与低风险档位

处理过程：

- 在相同合法动作集合上进行条件化评分
- 高风险档提高“上探替换”动作权重，低风险档提高“保底位移”动作权重

输出：

- 高风险组动作空间更偏收益导向
- 低风险组动作空间更偏稳健导向
